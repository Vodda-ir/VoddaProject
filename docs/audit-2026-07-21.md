# ممیزی تکمیل قابلیت‌ها و بدهی فنی — ۲۰۲۶-۰۷-۲۱

## دامنهٔ بررسی

- Backend Go/Gin/GORM/MySQL
- وب Next.js و BFF
- اپ Flutter/Android
- جریان‌های نقش، رزرو، مالی، پشتیبانی و انتشار عمومی
- تست، CI، seed، migration و عملیات

env و مقدارهای رمز طبق درخواست کاربر خارج از دامنهٔ بدهی فنی این گزارش هستند.

## خلاصهٔ نتیجه

در بررسی، چند بخش «ظاهراً کامل» اما در عمل ناقص یا گمراه‌کننده پیدا شد. موارد قابل حل داخل مخزن تکمیل شدند. مواردی که به سرویس یا زیرساخت خارجی نیاز دارند از UI فعال حذف و به‌عنوان بدهی باقی‌مانده مستند شدند.

## نقص‌های پیدا و رفع‌شده

### ۱. عملیات چندمرحله‌ای غیراتمیک

**مشکل:** ثبت استاد و امتیازدهی در چند write جدا انجام می‌شدند و failure می‌توانست دادهٔ نیمه‌کاره بسازد.

**رفع:**

- transaction اختصاصی برای ایجاد Teacher و تغییر role
- row lock و جلوگیری از profile تکراری
- transaction اختصاصی برای Review، Rated شدن Session و aggregate استاد
- تست همزمانی MySQL؛ فقط یک درخواست موازی موفق می‌شود

### ۲. نقش و وضعیت فعال فقط از JWT

**مشکل:** غیرفعال‌سازی حساب یا تغییر role تا انقضای JWT اعمال نمی‌شد.

**رفع:**

- امضای JWT همچنان بررسی می‌شود
- User در هر درخواست محافظت‌شده از دیتابیس خوانده می‌شود
- Active و Role جاری مرجع authorization هستند

### ۳. OTP خام در دیتابیس

**مشکل:** کد OTP قابل استفاده مستقیماً ذخیره می‌شد.

**رفع:**

- ذخیرهٔ HMAC-SHA256 digest با کلید سرور
- compare زمان‌ثابت
- سازگاری کوتاه‌مدت با رکوردهای قدیمی تا expire شدن آن‌ها

### ۴. فرم تماس نمایشی

**مشکل:** فرم فقط mailto بود و پیام قابل پیگیری نبود.

**رفع:**

- مدل و repository پیام پشتیبانی
- endpoint عمومی rate-limited
- BFF عمومی same-origin
- فرم واقعی با loading/error/success
- endpointهای فهرست و resolve برای ادمین

### ۵. نبود audit ادمین

**رفع:**

- ثبت mutationهای موفق ادمین با actor، action، target، request ID و metadata
- endpoint مشاهدهٔ audit log
- ثبت best-effort بعد از عملیات تا failure لاگ موجب تکرار mutation مالی نشود

### ۶. semantics خطرناک ورودی

**مشکل‌ها:**

- JSON نامعتبر در چند handler نادیده گرفته می‌شد
- `{}` در عملیات ادمین به false تبدیل می‌شد
- `weekday=0` نامعتبر تلقی می‌شد
- update خالی service می‌توانست state را تغییر دهد
- ID غیرعددی به ID صفر تبدیل می‌شد

**رفع:**

- رد JSON ناقص و فیلد ناشناخته
- pointer boolean برای عملیات حساس
- validation عمومی ID مثبت
- پشتیبانی درست از روز صفر
- قرارداد update صریح و جلوگیری از mutation ناخواسته

### ۷. فایل ناقص یا یتیم آواتار

**رفع:**

- ایجاد فایل با `O_EXCL`
- cleanup در copy failure و validation failure
- حفظ کنترل MIME، پسوند و حجم

### ۸. domain وابسته به hook دیتابیس

**رفع:**

- حذف import مستقیم GORM از domain
- normalize صریح در repositoryها
- normalize پروفایل preloadشده در `/me`

### ۹. داده و قابلیت ساختگی در UI

**حذف شد:**

- mock/fallback استاد هنگام قطع Backend
- آمار ثابت و testimonial ساختگی
- follower و follow بدون Backend
- اعلان fake
- تماس صوتی و join session بدون provider
- شارژ production بدون درگاه
- لینک دانلود `#`
- «استاد منتخب» بدون الگوریتم واقعی

UI اکنون empty/error state واقعی و وضعیت «به‌زودی» را نشان می‌دهد.

### ۱۰. جستجوی ناقص وب

**رفع:**

- Hero واقعاً query و city را به search منتقل می‌کند
- state فیلتر در URL نگه داشته می‌شود
- مقدارهای field با Backend یکسان‌اند
- aliasهای قدیمی برای سازگاری پذیرفته می‌شوند

### ۱۱. ذخیرهٔ JWT اپ در SharedPreferences

**رفع:**

- انتقال JWT به `flutter_secure_storage 10.3.1`
- lockfile کامل پلتفرم‌ها
- SharedPreferences فقط برای preference غیرحساس
- guard نقش در go_router
- پاک‌سازی نشست روی 401
- غیرفعال‌سازی Android backup/transfer داده‌های preference

### ۱۲. امضای debug برای Android release

**رفع:**

- Release بدون keystore واقعی fail می‌شود
- template امن `key.properties.example`
- secrets امضا در `.gitignore`
- minSdk متناسب با secure storage

### ۱۳. seed ناسازگار

**مشکل:** خطاهای Create نادیده گرفته می‌شد، IDها ثابت بودند و aggregate ساختگی ساخته می‌شد.

**رفع:**

- seed تراکنشی
- IDهای واقعی relation
- خطای صریح
- حذف rating/session/follower ساختگی

### ۱۴. پوشش تست ناکافی

**اضافه شد:**

- concurrency onboarding
- concurrency review و aggregate reconciliation
- route ID validation
- تست رگرسیون Node برای داده‌های عمومی، تماس و search
- enforce lockfile و lint مستقل در CI

## وضعیت اعتبارسنجی

workflow شامل این کنترل‌هاست:

- Backend: `gofmt`، `go vet`، `go test -race`، build و MySQL 8
- Frontend: `npm ci`، regression test، ESLint و Next build
- Flutter: `flutter pub get --enforce-lockfile`، analyze و test
- Deployment: shell syntax و Docker Compose config

با این حال، در تاریخ ممیزی تمام jobهای GitHub Actions **پیش از اولین step** و بدون log متوقف شدند. بنابراین:

- این وضعیت مدرک failure کد یا تست نیست.
- در عین حال نمی‌توان ادعا کرد commit نهایی در CI اجرا و سبز شده است.
- رفع وضعیت Actions و اجرای کامل workflow پیش از release الزامی است.
