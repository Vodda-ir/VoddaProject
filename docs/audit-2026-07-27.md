# ممیزی فنی و UI/UX وُدّا — ۲۰۲۶-۰۷-۲۷

## دامنهٔ بررسی

- Backend با Go، Gin، GORM و MySQL
- وب عمومی و پنل‌های Next.js
- اپ Flutter برای قرآن‌آموز و استاد
- احراز هویت، جستجو، رزرو، لغو، کیف پول، مدیریت و پشتیبانی
- responsive، accessibility پایه، error state و صداقت محتوای محصول
- تست، CI و بدهی فنی باقی‌مانده

## خلاصهٔ مدیریتی

هستهٔ مالی و امنیتی پروژه در ممیزی قبلی سخت‌سازی شده بود، اما این دور چند شکاف مهم در «اتصال UI به Backend» و «تجربهٔ واقعی کاربر» پیدا شد. مهم‌ترین موارد عبارت بودند از استفادهٔ بخشی از پنل وب از مسیر API حذف‌شده، نمایش قابلیت‌های بیرونیِ پیاده‌نشده، تولید نادرست ساعت رزرو، فیلترهای نمایشی در Flutter، نمودار ساختگی در داشبورد و نبود UI برای پشتیبانی و audit.

موارد قابل حل داخل مخزن در این تغییر تکمیل شدند. قابلیت‌هایی که به provider یا محیط واقعی نیاز دارند همچنان صریحاً غیرفعال و در بخش بدهی باقی‌مانده ثبت شده‌اند.

## نقص‌های فنی پیدا و رفع‌شده

### ۱. مسیرهای API شکسته در پنل وب

**مشکل:** چند صفحهٔ قدیمی هنوز به `/api/v1/...` درخواست می‌زدند، در حالی که نشست امن وب از `/api/backend` عبور می‌کند و rewrite قبلی حذف شده بود. این مسئله می‌توانست فهرست‌ها و mutationهای پنل را به 404 یا عملیات بی‌اثر تبدیل کند.

**رفع:**

- افزودن rewrite سازگاری `/api/v1/:path*` به `/api/backend/:path*`
- انتقال مستقیم صفحات اصلی به BFF
- عدم اعتماد به Authorization ساخته‌شده در JavaScript؛ JWT فقط از cookie HttpOnly تزریق می‌شود
- تست رگرسیون برای حفظ مسیر سازگاری

### ۲. تولید اشتباه زمان رزرو

**مشکل:** بازهٔ کاری ۹ تا ۱۲ فقط به‌صورت یک زمان ۹:۰۰ نمایش داده می‌شد و Flutter هم مدت همهٔ خدمات را ۳۰ دقیقه فرض می‌کرد.

**رفع:**

- utility مستقل slot generation در وب و Flutter
- تقسیم بازه بر اساس مدت خدمت انتخاب‌شده
- عدم ساخت slotی که از انتهای بازه عبور کند
- نمایش امروز و ۱۴ روز آینده
- حذف زمان‌های گذشته یا کمتر از پنج دقیقه تا شروع
- تست ۳۰ و ۶۰ دقیقه، بازهٔ ناقص، امروز و دادهٔ نامعتبر

### ۳. لغو جلسه پس از زمان شروع

**مشکل:** Backend مالکیت و وضعیت جلسه را بررسی می‌کرد، اما learner می‌توانست جلسهٔ گذشته را نیز لغو کند.

**رفع:**

- policy صریح `CancelBeforeStart`
- الزام pending/confirmed بودن، مالکیت learner و پیش از زمان شروع بودن
- استفاده از همان transaction اتمیک refund
- تست عدم mutation برای جلسهٔ شروع‌شده و refund کامل برای جلسهٔ آینده

### ۴. پاسخ قدیمی در جستجوی وب

**مشکل:** هنگام تایپ سریع، پاسخ کند درخواست قبلی می‌توانست نتایج فیلتر جدید را overwrite کند. همچنین فقط تعداد صفحهٔ فعلی نمایش داده می‌شد.

**رفع:**

- debounce ۳۵۰ میلی‌ثانیه‌ای
- `AbortController` برای درخواست قبلی
- total واقعی Backend و pagination
- همگام‌سازی query، city، field، female و page با URL

### ۵. فیلترهای نمایشی Flutter

**مشکل:** فیلترهای حوزه فقط بعد از دریافت یک لیست محدود روی کلاینت اعمال می‌شدند و گزینه‌های «امتیاز بالا» و «نزدیک من» هیچ منطق واقعی نداشتند.

**رفع:**

- فیلتر server-side نام، حوزه، شهر و جنسیت
- debounce جستجو
- bottom sheet فیلتر واقعی
- حذف کنترل‌های بی‌اثر
- retry و pull-to-refresh روی همان filter object

### ۶. داشبورد و دادهٔ ساختگی

**مشکل:** نمودار مدیریت با آرایهٔ ثابت ماهانه رسم می‌شد و بعضی خطاهای API به‌صورت صفر یا لیست خالی نمایش داده می‌شدند.

**رفع:**

- حذف نمودار ثابت
- نمایش فقط آمار واقعی endpoint مدیریت
- تفکیک loading، error و empty state
- پیام شفاف دربارهٔ نبود endpoint گزارش تاریخی

## بهبودهای UI/UX

### وب عمومی

- ناوبری پایین موبایل به‌جای مخفی‌شدن کامل منو
- focus-visible برای استفاده با صفحه‌کلید
- احترام به `prefers-reduced-motion`
- responsive شدن فرم جستجو، کارت‌ها و فاصلهٔ پنل‌ها
- نتیجهٔ بدون امتیاز به‌جای نمایش ۰٫۰ گمراه‌کننده

### پنل قرآن‌آموز

- حذف دکمه‌های شارژ development از production
- حذف CTA «پیوستن» تا زمان اتصال تماس صوتی واقعی
- نمایش جزئیات جلسه، زمان واقعی و وضعیت مالی
- confirmation و busy state برای لغو
- retry در داشبورد، جلسات و کیف پول

### پنل مدیر

- confirmation و بررسی پاسخ Backend برای عملیات حساس
- pagination کاربران
- جدول‌های دارای scroll افقی امن
- هشدار اینکه ثبت برداشت پرداخت‌شده جایگزین انتقال بانکی نیست
- صندوق پیام‌های پشتیبانی و قابلیت resolve
- صفحهٔ audit log برای پیگیری actor، action، target و request ID

### محتوای حقوقی و اعتماد محصول

- FAQ دیگر تماس صوتی و درگاه پرداخت را فعال معرفی نمی‌کند
- قوانین با policy واقعی لغو و refund هماهنگ شد
- حریم خصوصی از عبارت‌های تضمینی حذف و معماری واقعی نشست/لاگ توضیح داده شد

## بدهی فنی باقی‌مانده

### P0 — قابلیت بیرونی

1. زرین‌پال واقعی: authority، redirect، callback، verify، idempotency و reconciliation
2. provider تماس صوتی: token، room policy، reconnect، timeout و failure handling

### P1 — پایداری و عملیات

3. migration نسخه‌دار و حذف اتکای نهایی production به AutoMigrate
4. ممیزی و اعمال foreign keyها با migration و rollback آزموده‌شده
5. Redis/shared limiter و object storage برای چند replica
6. metrics، tracing، alerting و داشبورد عملیاتی
7. staging smoke/E2E برای نقش، رزرو، refund، settlement، withdrawal و restore

### P2 — کیفیت و انتشار

8. accessibility audit کامل با screen reader و ابزار خودکار
9. archive/signing واقعی iOS و آزمون Keychain روی device
10. build امضاشده و rollout/rollback فروشگاه‌های هدف

## محدودیت اعتبارسنجی فعلی

Workflow مخزن Go format/vet/race/build، MySQL integration، Node regression/lint/build، Flutter analyze/test و Docker validation را تعریف می‌کند. در اجرای قبلی GitHub Actions، jobها پیش از اولین step و بدون log متوقف می‌شدند؛ بنابراین این مشکل باید در سطح Actions/حساب مخزن رفع و workflow کامل دوباره اجرا شود. نبود اجرای step به معنی failure کد اثبات‌شده نیست، اما جایگزین CI سبز نیز محسوب نمی‌شود.

## جمع‌بندی

پس از این اصلاحات، جریان‌های اصلی وب و Flutter با قرارداد Backend هم‌راستا هستند، UI قابلیت ساختگی فعال نشان نمی‌دهد، فلو رزرو بر اساس بازه و مدت واقعی کار می‌کند و ابزارهای ضروری مدیریت در خود پنل قابل استفاده‌اند. موانع اصلی انتشار عمومی دیگر نقص پنهان UI نیستند؛ عمدتاً سرویس‌های بیرونی، migration/observability و آزمون staging هستند.
