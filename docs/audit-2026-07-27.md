# ممیزی فنی و UI/UX وُدّا — تکمیل در ۲۰۲۶-۰۷-۳۰

## دامنهٔ بررسی

- Backend با Go، Gin، GORM و MySQL
- وب عمومی و پنل‌های قرآن‌آموز، استاد و مدیر در Next.js
- اپ Flutter برای قرآن‌آموز و استاد
- احراز هویت، جستجو، رزرو، جلسه، کیف پول، برداشت، moderation، پشتیبانی و audit
- responsive، accessibility پایه، error state و صداقت محتوای محصول
- تست، CI و موانع انتشار

## خلاصهٔ مدیریتی

هستهٔ امنیتی و مالی پروژه قبلاً سخت‌سازی شده بود، اما ممیزی UI/UX چند شکاف عملکردی مهم پیدا کرد: صفحات متصل به مسیر API قدیمی، slot رزرو ناقص، اختلاف timezone میان Backend و دستگاه کاربر، قابلیت‌ها و آمار ساختگی، فیلترهای بی‌اثر، پنل استاد ناقص، endpoint اشتباه نظرها و برداشت Flutter که به‌علت نداشتن کارت/شبا همیشه توسط Backend رد می‌شد.

تمام موارد قابل حل داخل مخزن اصلاح شدند. موانع باقی‌مانده عمدتاً سرویس بیرونی، migration/observability و validation در staging هستند.

## نقص‌های P0 پیدا و رفع‌شده

### ۱. مسیرهای API شکسته و نشست وب

**مشکل:** بخشی از پنل‌ها به `/api/v1` می‌زدند، درحالی‌که JWT وب فقط در cookie HttpOnly و BFF قابل استفاده است.

**رفع:**

- rewrite سازگاری `/api/v1/:path*` به `/api/backend/:path*`
- انتقال مستقیم مسیرهای اصلی به BFF
- عدم ذخیره یا ساخت JWT در JavaScript
- تست رگرسیون برای cookie و forwarding امن

### ۲. availability و رزرو

**مشکل:** یک بازهٔ ۹ تا ۱۲ در وب فقط ۹:۰۰ تولید می‌کرد، Flutter مدت همهٔ خدمات را ۳۰ دقیقه فرض می‌کرد و منطق کلاینت از timezone دستگاه استفاده می‌کرد.

**رفع:**

- انتقال کامل slot generation به Backend به‌عنوان منبع حقیقت
- تقسیم بازه بر اساس مدت واقعی خدمت
- حذف زمان گذشته، slot ناقص و زمان دارای تداخل pending/confirmed
- بازگرداندن UTC برای submit و `local_*` رسمی برای نمایش
- refresh خودکار availability پس از conflict یا خطای ثبت
- تست Go برای timezone، تداخل، بازه و مدت خدمت

### ۳. اختلاف ساعت جلسه پس از رزرو

**مشکل:** availability ساعت رسمی سامانه را نشان می‌داد، اما فهرست جلسات Flutter و بعضی صفحات وب `scheduled_at` UTC را با timezone دستگاه نمایش می‌دادند؛ کاربر خارج از ایران می‌توانست ساعت متفاوتی ببیند.

**رفع:**

- قرارداد مشترک `SessionDisplay` در Backend
- حفظ `scheduled_at` UTC
- افزودن `local_date`، `local_start`، `local_end` و `weekday`
- استفاده از همین قرارداد در فهرست learner، teacher و admin
- حذف تبدیل ساعت در وب و Flutter
- تست Go و Flutter برای جلوگیری از بازگشت اختلاف timezone

### ۴. لغو پس از شروع

**مشکل:** learner می‌توانست جلسهٔ گذشته را لغو کند.

**رفع:**

- policy صریح لغو فقط برای مالک، وضعیت pending/confirmed و پیش از زمان شروع
- refund اتمیک
- تست عدم mutation جلسهٔ شروع‌شده و refund جلسهٔ آینده

### ۵. پنل استاد وب

**مشکل‌ها:**

- امتیاز `۴.۸` و نمودار درآمد ثابت
- accept/reject بدون کنترل پاسخ
- زمان جلسه وابسته به مرورگر
- نظرها از شمارندهٔ عددی `/teacher/me` به‌عنوان آرایه خوانده می‌شدند
- استاد امکان تلاش برای فعال‌سازی خدمت را می‌دید
- صفحهٔ برداشت کامل نبود

**رفع:**

- داشبورد فقط با موجودی، درخواست، جلسه، امتیاز و نظر واقعی
- حذف نمودار و درآمد دوره‌ای بدون endpoint گزارش
- confirmation، busy، error و retry برای عملیات
- endpoint واقعی `/teacher/reviews`
- moderation خدمت: استاد فقط غیرفعال می‌کند؛ انتشار مجدد با مدیر
- مدت خدمت ۱۰ تا ۲۴۰ دقیقه مطابق Backend
- CRUD برنامهٔ کاری با نمایش خطای هم‌پوشانی
- فرم برداشت با کنترل موجودی، کارت/شبا و تاریخچهٔ وضعیت

### ۶. پنل استاد Flutter

**مشکل‌ها:**

- نام خود استاد به‌جای قرآن‌آموز در کارت جلسه
- CTA «شروع جلسه» بدون provider واقعی
- امتیاز چهارتایی و fallback `۴.۸`
- «درآمد این ماه» بر اساس مجموع همهٔ تراکنش‌های مثبت
- برداشت فقط با amount و بدون مقصد بانکی؛ نتیجه همیشه validation error
- وعدهٔ بدون پشتوانهٔ واریز ۲۴ تا ۷۲ ساعت
- toggle فعال‌سازی خدمت خلاف policy moderation

**رفع:**

- نام learner، زمان رسمی و note واقعی
- عملیات واقعی accept/reject/complete و busy state
- حذف تماس، اعلان، امتیاز و درآمد ساختگی
- داشبورد با wallet/rating/reviews/sessions واقعی
- برداشت با کارت ۱۶ رقمی یا شبا `IR` + ۲۴ رقم
- توضیح رزرو مبلغ تا تعیین وضعیت، بدون وعدهٔ زمانی
- ویرایش خدمت ۱۰ تا ۲۴۰ دقیقه و فقط امکان deactivate

- حذف «نزدیک من» و «امتیاز بالا» بدون پیاده‌سازی
- ناوبری موبایل، focus-visible و reduced-motion
- responsive شدن جدول‌ها، فرم‌ها و کارت‌ها
- تفکیک loading، empty، error و retry

- نمودار، follower، rating، درآمد و CTA ساختگی حذف شده‌اند

## محدودیت اعتبارسنجی

Workflow مخزن این مراحل را تعریف می‌کند:

- Go format/vet/race/build و integration با MySQL
- Node regression/lint/Next build
- Flutter analyze/test
- Docker Compose validation

بااین‌حال، در runهای commit نهایی هر چهار job پیش از checkout و با `steps: null` خاتمه یافته‌اند و log مرحله‌ای ندارند. بنابراین:

- failure فعلی، خطای build/test کد را اثبات نمی‌کند؛
- بازبینی این PR بر اساس قراردادها، typeها، تست‌های منبع و بررسی ایستا انجام شده است؛
- پیش از انتشار عمومی، runner حساب/مخزن باید اصلاح و workflow کامل دوباره اجرا شود.
